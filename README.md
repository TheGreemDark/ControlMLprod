# ControlMLprod

Учебный проект по дисциплине
«Управление продуктами искусственного интеллекта на разных этапах жизненного цикла».

## Требования

- Python 3.13
- uv
- Git
- Unix / macOS / Linux / WSL
- make

## Данные

### Хранилище S3

Для хранения исходных и обработанных данных используется локальное S3-совместимое хранилище RustFS, запускаемое через Docker Compose.

Параметры хранилища:

- S3 API: `http://localhost:9000`
- Веб-интерфейс: `http://localhost:9001`
- Бакет: `controlmlprod-data`
- Переменные окружения: `S3_ENDPOINT_URL`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_BUCKET`, `AWS_DEFAULT_REGION`

Перед запуском необходимо настроить файл `.env` на основе `.env.example`.

Поднять хранилище:

```bash
make s3-up
```

Открыть веб-интерфейс RustFS по адресу `http://localhost:9001`. Доступ к хранилищу осуществляется с использованием учётных данных, указанных в `.env`.

Проверить содержимое бакета можно через веб-интерфейс или программно с помощью S3-клиента.

Остановить хранилище:

```bash
make s3-down
```

Команда останавливает сервисы Docker Compose, но не удаляет именованный том с данными.

### Порядок запуска конвейера

Перед первым запуском установите зависимости и настройте окружение:

```bash
make setup
```

Далее выполните команды в следующем порядке:

1. Запустите локальное S3-хранилище:

   ```bash
   make s3-up
   ```

2. Загрузите исходные данные CIFAR-10 в S3:

   ```bash
   make ingest
   ```

3. Запустите конвейер обработки данных:

   ```bash
   make data
   ```

4. При необходимости проверьте код и типы:

   ```bash
   make check
   ```

Команда `make ingest` загружает исходный датасет в хранилище. Команда `make data` выполняет конвейер обработки: подготовку аннотаций, разбиение обучающей выборки, расчёт статистик и публикацию обработанного набора данных в S3.

### Содержимое S3

Обработанный датасет публикуется в бакете `controlmlprod-data` по префиксу:

```text
processed/cifar10/v1/
```

Номер версии задаётся переменной `DATASET_VERSION`. По умолчанию используется `v1`. Для публикации новой версии необходимо указать, например, `DATASET_VERSION=v2`.

Ожидаемая структура опубликованных данных:

```text
processed/
└── cifar10/
    └── v1/
        ├── annotations/
        │   ├── train.json
        │   ├── val.json
        │   └── test.json
        ├── stats.json
        ├── manifest.json
        └── ... файлы изображений
```

Фактическое расположение изображений определяется структурой выходного каталога конвейера.

Назначение файлов:

- `train.json` — аннотации обучающей выборки;
- `val.json` — аннотации валидационной выборки;
- `test.json` — аннотации тестовой выборки;
- `stats.json` — статистики RGB-каналов обучающей выборки;
- `manifest.json` — метаданные публикации, размеры выборок, параметры разбиения, Git commit и контрольные суммы SHA-256.

Файл `train_all.json`, содержащий исходные 50 000 обучающих записей до разбиения, не публикуется в обработанном наборе данных.

Каждая версия датасета публикуется отдельно. Если в S3 уже существуют объекты под выбранным префиксом версии, публикация прекращается, чтобы избежать перезаписи ранее опубликованных данных.

### Карточка датасета: CIFAR-10

**Источник:** CIFAR-10, официальный набор данных для классификации изображений, распространяемый исследовательской группой University of Toronto.

**Состав:** 60 000 цветных изображений размером 32 × 32 пикселя, представленных тремя RGB-каналами.

**Классы:** 10 категорий — `airplane`, `automobile`, `bird`, `cat`, `deer`, `dog`, `frog`, `horse`, `ship`, `truck`.

**Исходное разбиение:**

- 50 000 обучающих изображений;
- 10 000 тестовых изображений.

**Разбиение в проекте:**

- train — 45 000 изображений;
- validation — 5 000 изображений;
- test — 10 000 изображений из исходной тестовой выборки.

Обучающая выборка разделяется с помощью `train_test_split` из scikit-learn со стратификацией по меткам классов. По умолчанию используется seed `42`, размер валидационной выборки — `5000`. Параметры можно переопределить через `SPLIT_SEED` и `VAL_SIZE`.

**Предобработка и статистики:** изображения преобразуются в RGB, значения пикселей нормализуются в диапазон `[0, 1]` при расчёте статистик. Среднее и стандартное отклонение вычисляются отдельно для каждого цветового канала на обучающей выборке.

**Известные ограничения:**

- CIFAR-10 содержит небольшие изображения, поэтому мелкие детали объектов могут быть плохо различимы.
- Датасет предназначен для классификации по десяти фиксированным классам и не отражает всё разнообразие реальных изображений.
- Статистики рассчитываются только на обучающей выборке, чтобы не использовать валидационные и тестовые данные при определении параметров нормализации.
- Для воспроизводимости необходимо сохранять исходные данные, параметры разбиения и версию датасета.
- При ошибке во время загрузки S3-публикация может оказаться частичной. Перед повторным запуском необходимо проверить состояние выбранного префикса.
